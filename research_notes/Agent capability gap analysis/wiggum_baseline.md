# Wiggum Agent-Capability Baseline (local repository, 2026-11-22)

## Key question 1: What are the user-facing capabilities and guarantees in the current tree?

### Takeaway
Wiggum is an orchestration shell around an agent CLI: eleven commands cover project init, plan/explain, execute, check, docs, a continuous-session `run`, machine-wide supervision (`status`/`watch`/`kill`/`top`), and chained plans. Its stated guarantees are bounded iterations and retries, verification against the project's own tools, plan- and issue-bookkeeping, scoped process kills, and read-only analysis modes.

### Cited Findings
- The README defines wiggum as "a self-driving agent loop that turns issue descriptions into working, verified code"; Claude Code is the default, with `opencode`, `pi` and `codex` using the same CLI — [README.md:3-5](/Users/ben/wiggum/README.md#L3-L5).
- Command surface: `init`, `plan`, `explain`, `execute`, `check`, `docs`, `run`, `status`, `watch`, `kill`, `chain`, `top` — [README.md:817-829](/Users/ben/wiggum/README.md#L817-L829). ## Key question 2: What does wiggum add that an agent CLI does not provide by itself?

### Takeaway
Within this codebase's design the agent CLI is a prompt executor; wiggum owns persistent plan state, verification policy, retry policy, process supervision, issue-ledger closure and scheduling. Those orchestration layers are the differentiator described in README and implemented in `lib/wiggum.sh`.

### Cited Findings
- The adapter contract says the loop is agent-independent: callers speak one vocabulary (one-shot prompt, `-c` to continue, effort/permission/model), and each adapter only turns that into argv, captures session ids and names failure markers — [lib/wiggum.sh:3056-3066](/Users/ben/wiggum/lib/wiggum.sh#L3056-L3066).
- A durable, agent-independent workplan format with checkboxes, observable acceptance criteria, critical path and risk gates is generated and consumed by wiggum — [README.md:122-150](/Users/ben/wiggum/README.md#L122-L150); [lib/wiggum.sh:3560-3664](/Users/ben/wiggum/lib/wiggum.sh#L3560-L3664).
- Verification is wiggum-owned: ordered shell commands from the user's config, autofix-then-check semantics, 60-line error capture, escalation prompt, full-waterfall restart and retry cap — [lib/wiggum.sh:3730-3804](/Users/ben/wiggum/lib/wiggum.sh#L3730-L3804); [.wiggumrc.example:8-26](/Users/ben/wiggum/.wiggumrc.example#L8-L26).
- Progress and stopping are computed by wiggum from markdown checkbox counts, with `[~]` as a terminal state; an agent CLI has no such plan-level instrument — [lib/wiggum.sh:1384-1448](/Users/ben/wiggum/lib/wiggum.sh#L1384-L1448); [lib/wiggum.sh:4076-4126](/Users/ben/wiggum/lib/wiggum.sh#L4076-L4126).
- Session lifecycle is managed across calls: generated id per attempt, retry with fork from the original predecessor, persisted id for cron follow-ups — [lib/wiggum.sh:3332-3348](/Users/ben/wiggum/lib/wiggum.sh#L3332-L3348); [README.md:344-356](/Users/ben/wiggum/README.md#L344-L356).
- Machine-wide supervision exists outside the agent session: run registry at `~/.wiggum/runs` for live runs plus local sidecars, `top` with process-tree RSS/CPU and host load/swap, pidfile identity/start time and exit-code taxonomy — [README.md:368-416](/Users/ben/wiggum/README.md#L368-L416); [README.md:460-471](/Users/ben/wiggum/README.md#L460-L471); [lib/wiggum.sh:4190-4278](/Users/ben/wiggum/lib/wiggum.sh#L4190-L4278).
- Chaining and delayed execution are wiggum-level: stop at first failed plan, queue re-read after each plan, one-shot `--at` with cancellation and no recurring artifacts — [README.md:473-585](/Users/ben/wiggum/README.md#L473-L585).
- Documentation and issue-ledger closure are phases of the loop, with explicit "do not invent or close remote trackers" rules — [lib/wiggum.sh:3662-3664](/Users/ben/wiggum/lib/wiggum.sh#L3662-L3664); [lib/wiggum.sh:4142-4157](/Users/ben/wiggum/lib/wiggum.sh#L4142-L4157).
- Benchmarks are a wiggum-specific feedback channel: user shell commands run after each commit and their numbers are injected into the next iteration; changed numbers count as progress — [README.md:1032-1035](/Users/ben/wiggum/README.md#L1032-L1035); [lib/wiggum.sh:3831-3845](/Users/ben/wiggum/lib/wiggum.sh#L3831-L3845); [lib/wiggum.sh:4066-4110](/Users/ben/wiggum/lib/wiggum.sh#L4066-L4110).
- Prompt discipline is centralised: all prompts end with "Do not ask for confirmation -- just do it.", plan files are declared as the only plan, and commit prompts mandate single-line imperative messages with no trailers — [lib/wiggum.sh:3562-3568](/Users/ben/wiggum/lib/wiggum.sh#L3562-L3568); [lib/wiggum.sh:3672-3693](/Users/ben/wiggum/lib/wiggum.sh#L3672-L3693).
- Init and config are wiggum-level project onboarding: presets, config search order, skill/rule/AGENTS/OpenCode installation — [lib/wiggum.sh:349-485](/Users/ben/wiggum/lib/wiggum.sh#L349-L485); [lib/wiggum.sh:1595-1726](/Users/ben/wiggum/lib/wiggum.sh#L1595-L1726).

## Key question 3: What does wiggum assume about agent CLIs?

### Takeaway
Wiggum assumes every CLI accepts prompt-and-files argv, one `-c`-style continuation, one effort value, one permission value, one model value, and either accepts a wiggum-generated session id or emits a parseable id in JSON. Failure is decided by exit code, with regex markers used only to explain the cause.

### Cited Findings
- Validation accepts exactly four agents, five effort levels (`low|medium|high|xhigh|max`) and six permission modes (`acceptEdits|auto|bypassPermissions|default|dontAsk|plan`) — [lib/wiggum.sh:132-158](/Users/ben/wiggum/lib/wiggum.sh#L132-L158).
- All callers inject `--effort`, `--permission-mode` and optionally `--model` into one `AGENT_INJECTED_ARGS` array; `-p`/`--print` is stripped, `-c`/`--continue` becomes a `wants_continue` boolean, and prompt/file tokens go into `AGENT_PROMPT_ARGS` — [lib/wiggum.sh:3290-3339](/Users/ben/wiggum/lib/wiggum.sh#L3290-L3339).
- Claude adapter passes injected/extra args verbatim, uses `--session-id <uuid>` and, on continuation, `--resume <prior> --fork-session`; wiggum owns the id — [lib/wiggum.sh:3099-3109](/Users/ben/wiggum/lib/wiggum.sh#L3099-L3109).
- OpenCode adapter assumes `run --format json`, continuation via `--session <prior> --fork`, `-m <model>`, `--variant <effort>` with `xhigh|max → max`, and a hardcoded `--auto`; it expects the CLI to report `sessionID` in JSON — [lib/wiggum.sh:3111-3131](/Users/ben/wiggum/lib/wiggum.sh#L3111-L3131); [test/wiggum.bats:8992-9022](/Users/ben/wiggum/test/wiggum.bats#L8992-L9022).
- Pi adapter assumes `--print`, `--session-id <uuid>`, `--fork <prior> --session-id <uuid>`, `--model`, and `--thinking <effort>`; wiggum owns the id — [lib/wiggum.sh:3133-3148](/Users/ben/wiggum/lib/wiggum.sh#L3133-L3148); [test/wiggum.bats:9024-9042](/Users/ben/wiggum/test/wiggum.bats#L9024-L9042).
- Codex adapter assumes `exec`, `exec fork <prior>`, `--json`, a single joined prompt string, `--sandbox` mapped from permission mode, `-a never`, `--model`, and `-c model_reasoning_effort=<effort>` with `max → xhigh`; it expects `thread_id` in JSON — [lib/wiggum.sh:3150-3184](/Users/ben/wiggum/lib/wiggum.sh#L3150-L3184); [test/wiggum.bats:9044-9072](/Users/ben/wiggum/test/wiggum.bats#L9044-L9072).
- Session extraction uses regexes over captured stdout (`"sessionID"` for opencode, `"thread_id"` for codex); a missing id clears `WIGGUM_LAST_SESSION_ID` with a warning, so the next continuation starts a new session — [lib/wiggum.sh:3197-3212](/Users/ben/wiggum/lib/wiggum.sh#L3197-L3212); [lib/wiggum.sh:3370-3379](/Users/ben/wiggum/lib/wiggum.sh#L3370-L3379); [test/wiggum.bats:9074-9084](/Users/ben/wiggum/test/wiggum.bats#L9074-L9084).
- Resume hints are hard-coded per CLI: `claude --resume`, `opencode -s`, `pi --session`, `codex exec resume` — [lib/wiggum.sh:3214-3221](/Users/ben/wiggum/lib/wiggum.sh#L3214-L3221).
- Failure detection: exit code decides failure; `WIGGUM_CLAUDE_FAILURE_MARKERS` (API Error, connection closed, timeout, overload, rate limit, credit balance, invalid/OAuth token, prompt too long) plus per-agent additions only name the cause; a marker on exit 0 produces a warning — [lib/wiggum.sh:3225-3250](/Users/ben/wiggum/lib/wiggum.sh#L3225-L3250); [lib/wiggum.sh:3360-3369](/Users/ben/wiggum/lib/wiggum.sh#L3360-L3369).

## Key question 4: Where is the current mapping incomplete or lossy across claude/opencode/pi/codex?

### Takeaway
Claude is the only adapter that passes all three knobs natively. OpenCode discards the configured permission mode, collapses two effort levels, ignores extra CLI args and has a resume-hint mismatch; pi ignores permission entirely and passes effort verbatim; codex collapses six permission modes to three sandboxes plus one fixed approval policy and flattens argv into a single prompt string. Naming, docs and test coverage remain Claude-centred.

### Cited Findings
- Permission mapping: README says each agent maps the six Claude vocabulary values to its own flags — [README.md:930](/Users/ben/wiggum/README.md#L930). In code, opencode always appends `--auto` and never reads the injected permission value — [lib/wiggum.sh:3128](/Users/ben/wiggum/lib/wiggum.sh#L3128); pi has no permission handling — [lib/wiggum.sh:3133-3148](/Users/ben/wiggum/lib/wiggum.sh#L3133-L3148); codex maps `plan → read-only`, `bypassPermissions → danger-full-access`, everything else → `workspace-write`, and always adds `-a never` — [lib/wiggum.sh:3161-3166](/Users/ben/wiggum/lib/wiggum.sh#L3161-L3166).
- Effort mapping: validation accepts five levels for every agent — [lib/wiggum.sh:134-140](/Users/ben/wiggum/lib/wiggum.sh#L134-L140). OpenCode collapses `xhigh` and `max` into one `max` variant — [lib/wiggum.sh:3121-3127](/Users/ben/wiggum/lib/wiggum.sh#L3121-L3127); codex collapses `max` into `xhigh` — [lib/wiggum.sh:3168-3170](/Users/ben/wiggum/lib/wiggum.sh#L3168-L3170); pi forwards `xhigh`/`max` unchanged to `--thinking` — [lib/wiggum.sh:3145](/Users/ben/wiggum/lib/wiggum.sh#L3145). The adapter tests assert only `high` for opencode and `xhigh` for pi — [test/wiggum.bats:9002-9011](/Users/ben/wiggum/test/wiggum.bats#L9002-L9011); [test/wiggum.bats:9024-9032](/Users/ben/wiggum/test/wiggum.bats#L9024-L9032).
- Session ownership: wiggum generates a UUID for every attempt — [lib/wiggum.sh:3332-3339](/Users/ben/wiggum/lib/wiggum.sh#L3332-L3339). Claude and pi use that id — [lib/wiggum.sh:3101-3104](/Users/ben/wiggum/lib/wiggum.sh#L3101-L3104); [lib/wiggum.sh:3138-3143](/Users/ben/wiggum/lib/wiggum.sh#L3138-L3143).
