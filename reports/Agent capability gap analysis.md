# Agent primitives stop where wiggum starts

Claude Code, OpenCode, Pi and Codex all run a prompt, resume a session and select a model; none carries a workplan through verification to a commit. Wiggum keeps the state between calls: a markdown plan with checkbox control flow, an ordered verify and autofix waterfall, retry and stall counters, a machine-wide run registry, and per-task commit and ledger rules ([README.md:3-5](/Users/ben/wiggum/README.md#L3-L5); [README.md:122-173](/Users/ben/wiggum/README.md#L122-L173)). The 2026-11-22 research baseline found lossy adapters: OpenCode hardcoded `--auto`, Pi ignored permission, Codex used a fixed `-a never`, and wiggum's `default` mode was invalid for installed Claude v2.1.330 ([lib/wiggum.sh](/Users/ben/wiggum/lib/wiggum.sh); local `claude --help`, 2026-11-22; [CLI reference](https://code.claude.com/docs/en/cli-reference)). The same-day repair added the explicit mappings, warnings, CLI probes and Bats tests recorded below. Native agents still stop at the session boundary, so the plan, verification and supervision remain wiggum's job.

## Implementation status, 22 November 2026

The adapter findings below are the baseline that drove the repair. The current tree now accepts `manual` and keeps `default` as an alias mapped to `manual` for Claude. OpenCode maps `plan` to `--agent plan` and `bypassPermissions` to `--auto`; other modes use configured permissions with a warning. Pi maps `plan` to `--tools read,grep,find,ls` and `acceptEdits` to edit and write tools without `bash`; other modes warn that Pi uses process permissions. Codex maps `plan` to `--sandbox read-only`, `bypassPermissions` to `--dangerously-bypass-approvals-and-sandbox`, `acceptEdits`/`auto`/`dontAsk` to `workspace-write` with `--approve-for-me`, and `manual`/`default` to `workspace-write` with a warning. The invalid `-a never` flag is gone. `xhigh` on OpenCode and `max` on Codex print a warning when collapsed to the nearest supported effort.

Pi was installed with `npm install -g --ignore-scripts @earendil-works/pi-coding-agent` and reports `pi --version` 1.6.0. A direct `pi --no-context-files --print "Reply with exactly: OK"` failed with `No API key found for the selected model.`, so a real Pi model run still needs provider login. Codex was installed with `npm install -g @openai/codex` and reports `codex-cli 0.171.0`; its `exec --help` has no `-a` flag, which explains the removal. No real Codex model run was attempted. The root `CLAUDE.md` was renamed to `AGENTS.md`; `.claude/` kept its skills, rules and commands, and a generated `.agents/skills/wiggum/SKILL.md` was added for the other agents.

## Every agent runs a prompt; none advances a workplan

The comparison turns on where state lives. Claude Code saves plan text under `~/.claude/plans/` and keeps task records in session tools; OpenCode writes plan Markdown into its plans directory and offers an opt-in `todowrite`; Pi ships plan-mode and todo as example extensions; Codex keeps `/plan`, `/goal` and subagent threads inside a session ([Common workflows](https://code.claude.com/docs/en/common-workflows); [Agents](https://opencode.ai/docs/agents); [Pi Extensions docs](https://docs.pi.dev/latest/extensions); [Developer commands](https://learn.chatgpt.com/docs/developer-commands.md)). None defines the fields wiggum treats as executable: benefits with observable signals, a backwards-derived critical path, per-task acceptance lines, `[ ]`/`[x]`/`[~]` state, risk gates and issue references ([README.md:122-173](/Users/ben/wiggum/README.md#L122-L173); [lib/wiggum.sh:1384-1448](/Users/ben/wiggum/lib/wiggum.sh#L1384-L1448)).

Execution primitives line up more closely. Each CLI offers a non-interactive prompt, a structured event stream, resume and fork, and some form of tool or sandbox control ([Headless](https://code.claude.com/docs/en/headless); [CLI](https://opencode.ai/docs/cli); [Pi CLI docs](https://docs.pi.dev/latest/cli); [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)). All four leave the caller to decide which commands verify a change, when a task counts as done, when to stop after repeated failure, how to commit and how to close a ledger entry. Wiggum supplies those rules from `.wiggumrc` and the plan file, which is why its adapter can stay thin ([lib/wiggum.sh:3290-3339](/Users/ben/wiggum/lib/wiggum.sh#L3290-L3339); [.wiggumrc.example:8-26](/Users/ben/wiggum/.wiggumrc.example#L8-L26)).

## Claude Code matches on effort and drifts on permission

A Claude Code v2.1.330 session can explore in plan mode, track work with `TaskCreate`, `TaskUpdate`, `TaskList` and `TaskGet`, hold a target across turns with `/goal`, and schedule recurring prompts, while a `Stop` hook can send failure text back for repair in the same turn ([Common workflows](https://code.claude.com/docs/en/common-workflows); [Goal](https://code.claude.com/docs/en/goal); [Scheduled tasks](https://code.claude.com/docs/en/scheduled-tasks); [Hooks guide](https://code.claude.com/docs/en/hooks-guide/)). Those surfaces stop at the session boundary: the saved plan has no documented schema a caller can advance, and the task tools vanish between sessions (local `claude --help`, 2026-11-22). Wiggum's workplan also carries a feedback pass that records open decisions and documentation audiences, which the native plan file does not represent ([README.md:134](/Users/ben/wiggum/README.md#L134); [lib/wiggum.sh:3410-3419](/Users/ben/wiggum/lib/wiggum.sh#L3410-L3419)).

Native transport covers one-shot `claude -p`, the Agent SDK, resume by flag, name, id, transcript path or pull request, `--session-id`, `--fork-session` and background sessions with `agents`, `attach`, `logs`, `stop`, `rm` and `respawn` ([Headless](https://code.claude.com/docs/en/headless); [Sessions](https://code.claude.com/docs/en/sessions); local `claude --help`, v2.1.330). Wiggum's Claude adapter adds little at that layer: it passes injected flags through, supplies its own id and forks the predecessor on retry ([lib/wiggum.sh:3099-3109](/Users/ben/wiggum/lib/wiggum.sh#L3099-L3109)). Its additions sit above the session, where the verification waterfall, autofix pass, sixty-line failure capture, attempt counter, bounded process-tree kills, machine-wide `top`, chain and one-shot `--at` have no native counterpart ([lib/wiggum.sh:3730-3804](/Users/ben/wiggum/lib/wiggum.sh#L3730-L3804); [README.md:360-471](/Users/ben/wiggum/README.md#L360-L471)). No measurement in the notes compares the two loops on reliability, latency or token spend.

The local CLI accepts `acceptEdits`, `auto`, `bypassPermissions`, `manual`, `dontAsk` and `plan`; the research baseline found wiggum validating `default` in place of `manual` and injecting it verbatim, which could reach the CLI as an invalid flag (local `claude --help`, v2.1.330; [lib/wiggum.sh:144-149](/Users/ben/wiggum/lib/wiggum.sh#L144-L149); [lib/wiggum.sh:3099-3109](/Users/ben/wiggum/lib/wiggum.sh#L3099-L3109)). The current Claude adapter maps `default` to `manual`. Tool-level switches such as `--tools`, `--allowedTools`, `--disallowedTools`, `--permission-prompts` and `--restricted` also fall outside a single mode string. **Permissions:** translate `default` to `manual` in the adapter before invoking the CLI, keep the other five values as-is, and expose finer tool control through `AGENT_EXTRA_ARGS` or a dedicated config key ([lib/wiggum.sh:3105-3106](/Users/ben/wiggum/lib/wiggum.sh#L3105-L3106)). **Effort:** keep `xhigh` as the default; local help lists `low`, `medium`, `high`, `xhigh` and `max`, and docs that mention `ultracode` belong to a different release line ([CLI reference](https://code.claude.com/docs/en/cli-reference)). **Model:** keep the `model_plan` and `model_execute` aliases; `--model` accepts aliases and provider names, while `ANTHROPIC_BASE_URL` redirects requests to a different endpoint ([Model config](https://code.claude.com/docs/en/model-config)). **Sessions:** keep wiggum's generated UUID and `--resume <prior> --fork-session`; native fork does the same job, so only the attempt accounting stays in wiggum. **Skills and config:** keep `.claude/skills/wiggum/SKILL.md`, `.claude/rules/wiggum.md` and the marked `AGENTS.md` block; `.agents/skills/` has no native discovery path, and exposing it to Claude needs a symlink under `.claude/skills/` ([Skills](https://code.claude.com/docs/en/skills); [Claude directory](https://code.claude.com/docs/en/claude-directory)).

## `AGENTS.md` works on v2.1.277; `.claude/` stays put

A rename from `CLAUDE.md` to `AGENTS.md` is supported once no `CLAUDE.md`, `.claude/CLAUDE.md` or `CLAUDE.local.md` remains in the working directory or a parent; reading `AGENTS.md` directly requires **Claude Code v2.1.277 or later** ([Memory](https://code.claude.com/docs/en/memory)). Those three files take precedence where they exist, while `~/.claude/CLAUDE.md`, managed `CLAUDE.md` and `.claude/rules` do not block `AGENTS.md`. At session start Claude reads every `AGENTS.md` and `.claude/AGENTS.md` from the working directory upward, and skips `AGENTS.local.md`, `AGENTS.override.md` and anything under a `.agents/` directory ([Memory](https://code.claude.com/docs/en/memory)). The installed v2.1.330 binary clears the version threshold, so wiggum's marked `AGENTS.md` block loads on every Claude run.

Renaming `.claude/` wholesale removes the directories Claude uses for project skills, rules and commands. Project skills load from **`.claude/skills/`**, and Claude Code has no native discovery path under `.agents/skills/`; a skill folder under `.claude/skills/` may be a symlink into `.agents/skills/`, which is how that content becomes discoverable ([Skills](https://code.claude.com/docs/en/skills); [Claude directory](https://code.claude.com/docs/en/claude-directory)). **Implementation:** keep `.claude/skills/wiggum/SKILL.md`, `.claude/rules/wiggum.md` and generated commands under `.claude/` for Claude-specific surfaces, keep the marked `AGENTS.md` block for other agents, and generate `.agents/skills/wiggum/SKILL.md` for agents that discover it there. The root `CLAUDE.md` to `AGENTS.md` rename is safe on v2.1.277+ after the old files are removed; a `.claude/` rename is not.

## OpenCode's plan agent is a permission profile

OpenCode V2 ships `build`, `plan`, `general` and `explore` agents plus hidden maintenance agents; `plan` is a read-only permission profile that may write plan files when asked and still runs permission-controlled shell commands ([Agents](https://opencode.ai/docs/agents)). Official pages disagree on where those files live, with `.opencode/plans/` on one page and `~/.opencode/plan` on another, and the V1 line needs `OPENCODE_EXPERIMENTAL_PLAN_MODE` to save them at all ([Agents](https://opencode.ai/docs/agents); [Permissions](https://opencode.ai/docs/permissions); [V1 CLI](https://opencode.ai/v1/docs/cli)). Todo tracking arrives only through `"experimental": { "todo": true }`, and `steps` caps model turns before tools are removed ([Config](https://opencode.ai/docs/config); [Agents](https://opencode.ai/docs/agents)). That gives wiggum's read-only `explain` a native analogue and nothing more: the plan file has no acceptance fields, progress counter or executor that consumes it.

The execution side is richer. `opencode run --format json` serves scripts and CI, `--session <id> --fork` and `--continue` control continuation, `-m` selects `provider/model`, `--agent` selects an agent, and the V2 HTTP API exposes fork, wait, agent and model switching on live sessions ([CLI](https://opencode.ai/docs/cli); [V1 CLI](https://opencode.ai/v1/docs/cli#run); [API reference](https://opencode.ai/docs/api)). Subagents run in background child sessions with depth one, shell calls can background themselves, and a shared server owns sessions and tool execution ([Agents](https://opencode.ai/docs/agents); [Tools](https://opencode.ai/docs/tools)). None of that supplies a verify then repair loop; the nearest built-in, `formatter`, reformats files after edits, and OpenCode has no commit step or machine-wide run registry ([Config](https://opencode.ai/docs/config); [wiggum_baseline.md:17-25](/Users/ben/wiggum/research_notes/Agent%20capability%20gap%20analysis/wiggum_baseline.md#L17-L25)).

The research baseline sent all OpenCode permission values through an unconditional `--auto`, which auto-approves everything the config does not deny; the fine-grained `allow`/`ask`/`deny` rules live in config files and cannot be expressed as per-call flags ([lib/wiggum.sh:3128](/Users/ben/wiggum/lib/wiggum.sh#L3128); [Permissions](https://opencode.ai/docs/permissions)). The current adapter uses `--agent plan` for `plan`, `--auto` for `bypassPermissions`, and warns when another mode falls back to configured permissions. Effort lost two levels in the baseline because `xhigh` and `max` both became the `max` variant; any variant name must exist in the selected model's catalog ([lib/wiggum.sh:3121-3127](/Users/ben/wiggum/lib/wiggum.sh#L3121-L3127); [Models](https://opencode.ai/docs/models)). `--thinking` only shows thinking blocks, so conflating it with effort would change behaviour ([CLI](https://opencode.ai/docs/cli)). **Permissions:** keep config-backed `allow`/`ask`/`deny` rules for the modes that need them. **Effort:** read the model catalog at run time, map `low`/`medium`/`high` directly and `xhigh`/`max` to the closest offered variant, define custom variants where the catalog lacks a name, and record the variant chosen. **Model:** pass `provider/model#variant` through `-m`. **Sessions:** keep JSON `sessionID` capture and `--session <id> --fork`; the failure hint `opencode -s <id>` matches installed OpenCode's top-level session flag ([lib/wiggum.sh:3117-3119](/Users/ben/wiggum/lib/wiggum.sh#L3117-L3119); [lib/wiggum.sh:3217](/Users/ben/wiggum/lib/wiggum.sh#L3217)). **Skills and config:** keep both `.opencode/commands/wiggum.md` and `.claude/skills/wiggum/SKILL.md`, since OpenCode discovers both natively, plus the `AGENTS.md` block; add a V1/V2 switch before relying on config keys ([Skills](https://opencode.ai/docs/skills); [Instructions](https://opencode.ai/docs/instructions)).

## Pi leaves the loop to extensions

Pi's core tools are `read`, `bash`, `powershell`, `edit`, `write`, `grep`, `find` and `ls`, with no built-in plan or todo tool ([Pi CLI docs](https://docs.pi.dev/latest/cli)). The installed package ships `plan-mode` and `todo` as examples: the first adds `/plan`, `--plan` and `[DONE:n]` tracking while disabling writes, the second registers a `todo` tool and stores state in tool results ([plan-mode README](/Users/ben/.nvm/versions/node/v24.11.1/lib/node_modules/@earendil-works/pi-coding-agent/examples/extensions/plan-mode/README.md); [todo.ts](/Users/ben/.nvm/versions/node/v24.11.1/lib/node_modules/@earendil-works/pi-coding-agent/examples/extensions/todo.ts)). Prompt templates, skills and `AGENTS.md`/`CLAUDE.md` files are user-driven instruction surfaces, so any plan artifact needs a convention layered on top ([Pi Prompt Templates docs](https://docs.pi.dev/latest/prompt-templates); [Pi Skills docs](https://docs.pi.dev/latest/skills)).

Execution primitives are strong. `--print` gives one-shot output, `--mode json` streams JSONL events with `agent_settled` marking the point where automatic work ends, and `--mode rpc` holds a bidirectional control channel for steer, follow-up, abort, compaction and retry ([Pi CLI docs](https://docs.pi.dev/latest/cli); [Pi JSON docs](https://docs.pi.dev/latest/json); [Pi RPC docs](https://docs.pi.dev/latest/rpc)). Sessions persist by default with branch, fork, clone and export, and retry plus compaction settings cover provider-level failures ([Pi Sessions docs](https://docs.pi.dev/latest/sessions); [Pi Settings docs](https://docs.pi.dev/latest/settings)). Extensions can intercept `tool_call` events and block commands, but project trust controls resource loading and Pi runs with process permissions, so a sandbox comes from the OS or a container ([Pi Extensions docs](https://docs.pi.dev/latest/extensions); [Pi Security docs](https://docs.pi.dev/latest/security)). Wiggum's verify and autofix waterfall, checkbox stopping rule, commit discipline and `status`/`watch`/`kill`/`top` remain caller-owned work.

The research baseline had the Pi adapter read effort and model and pass effort through `--thinking`, while it ignored the permission value ([lib/wiggum.sh:3133-3148](/Users/ben/wiggum/lib/wiggum.sh#L3133-L3148)). Pi has no permission enum to receive one. The current adapter maps `plan` to `--tools read,grep,find,ls` and `acceptEdits` to `--tools read,edit,write,grep,find,ls --exclude-tools bash`; other modes use the process tool set and print a warning. **Permissions:** keep the tool sets and warnings; add an external sandbox or extension gate for modes that need prompts or deny-on-prompt. **Effort:** pass `low` through `max` to `--thinking`, which accepts `off`, `minimal`, `low`, `medium`, `high`, `xhigh` and `max` and clamps to the model's capability, and leave `off`/`minimal` outside wiggum's enum ([Pi CLI docs](https://docs.pi.dev/latest/cli)). **Model:** keep `--model`. **Sessions:** keep wiggum's UUID with `--session-id` and `--fork <prior> --session-id <uuid>`; align the failure hint `pi --session` with that fork form ([lib/wiggum.sh:3218](/Users/ben/wiggum/lib/wiggum.sh#L3218)). **Skills and config:** the `AGENTS.md` block already loads; the generated `.agents/skills/wiggum/SKILL.md` gives Pi a skill surface, with project trust rules still applying to resource loading ([Pi Configuration docs](https://docs.pi.dev/latest/configuration); [Pi Security docs](https://docs.pi.dev/latest/security)).

## Codex brings review gates and three sandboxes

Codex offers `/plan` for conversational planning, `codex review` with `--uncommitted`, `--base` or `--commit`, `/goal` for a session objective capped at 4,000 characters, and `/subagents` with `multi_agent` config ([Developer commands](https://learn.chatgpt.com/docs/developer-commands.md); [Config reference](https://learn.chatgpt.com/docs/config-file/config-reference.md)). Session tools include `resume`, `fork`, `archive`, `delete` and `queue`. `codex exec` can be prompted to plan. No documented command consumes a file shaped like `docs/<slug>_plan.md` and drives it task by task ([Developer commands](https://learn.chatgpt.com/docs/developer-commands.md)). Goals and threads stay inside a session; wiggum's plan, ledger and summary files survive between calls.

On execution, `codex exec` streams progress to stderr and the final message to stdout, with `--json` producing JSONL events such as `thread.started`, `turn.failed` and `item.*`, `-o` writing the last message to a file and `--output-schema` constraining it ([Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode); [CLI reference](https://learn.chatgpt.com/docs/cli/reference.md)). Sandboxes are `read-only`, `workspace-write` and `danger-full-access`, approval is `on-request` or `never`, `--approve-for-me` pairs automatic review with `workspace-write`, and `--full-auto` has been removed for `exec` ([CLI reference](https://learn.chatgpt.com/docs/cli/reference.md); [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)). Hooks exist as a feature, yet the docs give no built-in verify, feed-back and retry loop with per-task commits ([Config basics](https://learn.chatgpt.com/docs/config-file/config-basic.md)). Wiggum's review gate is the verification waterfall and the ledger, while `codex review` examines code changes.

The research baseline had the Codex adapter map `plan` to `read-only`, `bypassPermissions` to `danger-full-access`, everything else to `workspace-write`, and add `-a never` on every call; `max` effort became `xhigh`, and the prompt plus its file paths were joined into one string ([lib/wiggum.sh:3150-3184](/Users/ben/wiggum/lib/wiggum.sh#L3150-L3184)). Installed `codex-cli 0.171.0` has no `-a` flag, so the current adapter uses sandbox and approval flags: `read-only` for `plan`, the bypass flag for `bypassPermissions`, `workspace-write` with `--approve-for-me` for `acceptEdits`/`auto`/`dontAsk`, and `workspace-write` with a warning for `manual`/`default`. **Permissions:** keep flag placement tied to the installed version because docs and `exec --help` differ ([CLI reference](https://learn.chatgpt.com/docs/cli/reference.md)). **Effort:** pass `low`, `medium`, `high` and `xhigh` through `model_reasoning_effort`; warn and use `xhigh` for `max` ([Config reference](https://learn.chatgpt.com/docs/config-file/config-reference.md); [Model selection](https://learn.chatgpt.com/docs/model-selection)). **Model:** keep `-m`. **Sessions:** keep `thread_id` capture and `exec fork <prior>`, align the recovery hint `codex exec resume` with the fork path the build uses, and quote each argument while joining so paths containing spaces survive intact ([lib/wiggum.sh:3219](/Users/ben/wiggum/lib/wiggum.sh#L3219); [lib/wiggum.sh:3172-3182](/Users/ben/wiggum/lib/wiggum.sh#L3172-L3182)). **Skills and config:** the generated `.agents/skills/wiggum/SKILL.md` gives Codex a skill surface, with the `AGENTS.md` block short enough for the 32 KiB `project_doc_max_bytes` cap ([Build skills](https://learn.chatgpt.com/docs/build-skills.md); [AGENTS.md docs](https://learn.chatgpt.com/docs/agent-configuration/agents-md.md)).

## Four adapters collapse the same three knobs

Permission, effort and session ownership accounted for most of the baseline loss ([lib/wiggum.sh:3099-3109](/Users/ben/wiggum/lib/wiggum.sh#L3099-L3109); [lib/wiggum.sh:3121-3128](/Users/ben/wiggum/lib/wiggum.sh#L3121-L3128); [lib/wiggum.sh:3133-3148](/Users/ben/wiggum/lib/wiggum.sh#L3133-L3148); [lib/wiggum.sh:3161-3170](/Users/ben/wiggum/lib/wiggum.sh#L3161-L3170)). Claude passed all three knobs natively apart from one stale value; OpenCode discarded permission and two effort levels, Pi discarded permission, and Codex discarded four permission distinctions and one effort level. The current adapters map every mode and warn where the mapping changes meaning. Session handling splits the same way: Claude and Pi accept wiggum's id, OpenCode and Codex replace it with an id parsed from stdout ([lib/wiggum.sh:3197-3212](/Users/ben/wiggum/lib/wiggum.sh#L3197-L3212)).

## Conclusion

Treat effort, permission and model as hints each adapter must validate, since the four CLIs disagree about all three. The current tree maps every config value and warns when an agent cannot enforce its original meaning. Wiggum's durable state earns its place in all four setups, and the open risk is that a thin adapter changes the conditions under which that state gets written.

The repair is testable with tools already in the repo: run one plan per adapter on a pinned CLI version, capture the argv each builder emits, and compare the resulting workplan, verification log and commit with `.wiggumrc`. Bats tests now cover the mapping matrix, including explicit permission flags, generated skill copies and the installed installer behavior.

## Uncertainties and version caveats

- **Claude Code:** local v2.1.330 help is the authority for flag values. Docs pages drawn from other releases mention `ultracode` and name modes differently, and release-notes webfetch output was truncated, so the reported 30-day retention for loop work and older changelog entries need a fresh check. The release that renamed `default` to `manual` was not found. No native run tested permission, effort, hooks or background agents.
- **OpenCode:** local binary 1.19.6 belongs to the V1 line while 2.3.2 is the current release; V2 `run --help` was never captured, and V1/V2 config keys and permission action names differ. Official pages disagree on plan file paths, and some permission detail came from cached V1 pages. Plugin-based verification hooks were not researched.
- **Pi:** installed 1.6.0 comes from `@earendil-works/pi-coding-agent`, while npm metadata queried described `@mariozechner/pi-coding-agent` 0.73.1, so docs labelled `latest` may not match the binary. No live RPC or JSON session was run, third-party planning extensions were not surveyed, and context-file precedence edge cases were not tested.
- **Codex:** the baseline had no local binary, so its flag statements came from official docs. The later `codex-cli 0.171.0` probe confirmed that `exec --help` has no `-a` flag and exposes `--sandbox`, `--approve-for-me` and the bypass flag. No model run was attempted, reasoning levels depend on the selected model, and JSON event schemas were not validated against a run.
- **Wiggum baseline:** the research phase stayed inside local files; the same-day repair added Bats argv tests and checks of installed CLI help. No data measures retry or stall frequency, and no benchmark compares the four agents on the same tasks.
